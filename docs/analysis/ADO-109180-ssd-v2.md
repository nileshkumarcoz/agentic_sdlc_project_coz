## 1. Proposed Architecture Overview

This revision extends the previous design by introducing a **fully implemented Login subsystem** as the security gateway to the entire platform. All other features (document upload, architecture generation, SAD management) are accessible only after successful authentication. The login subsystem is built into the existing `agentic_sdlc_project_coz` stack using FastAPI (backend) and React (frontend), following established platform patterns.

### 3.6 Security Components

| Component | Implementation |
|-----------|----------------|
| **Login Endpoint** | Rate-limited (10 req/min per IP via `slowapi`); lockout after 5 failed attempts |
| **Password Hashing** | `passlib` with bcrypt, cost factor 12 |
| **JWT Access Token** | HS256 / RS256, 15-minute expiry, includes `sub` (user_id), `role`, `jti` |
| **Refresh Token** | 7-day expiry; stored as httpOnly Secure SameSite=Strict cookie |
| **Token Denylist** | Redis SET keyed by `jti`; checked by JWT Middleware on every request |
| **RBAC** | FastAPI `Depends` decorators enforce role checks: `architect`, `reviewer`, `admin` |
| **Transport Encryption** | TLS 1.2+ on all endpoints |
| **Data Encryption at Rest** | S3/Blob SSE-AES-256; PostgreSQL encrypted volumes |
| **Input Sanitisation** | Strip macros from DOCX; remove embedded objects from PDF before LLM submission |
| **Audit Logging** | Auth events (login success/fail, logout) and agent invocations logged immutably |

### 6.1 Login Endpoint Logic
```python
# POST /api/v1/auth/login
async def login(request: LoginRequest, db: AsyncSession, redis: Redis):
    user = await db.execute(select(User).where(User.email == request.email))
    user = user.scalar_one_or_none()

    # Step 1: Check if account is locked
    if user and user.locked_until and user.locked_until > datetime.utcnow():
        await audit_service.log(action="LOGIN_FAILURE", email=request.email, reason="LOCKED")
        raise HTTPException(status_code=423, detail="Account locked. Try again later.")

    # Step 2: Verify password
    if not user or not security.verify_password(request.password, user.hashed_password):
        if user:
            user.failed_attempts += 1
            if user.failed_attempts >= 5:
                user.locked_until = datetime.utcnow() + timedelta(minutes=15)
                await audit_service.log(action="LOCKOUT", user_id=user.id)
            await db.commit()
        await audit_service.log(action="LOGIN_FAILURE", email=request.email)
        raise HTTPException(status_code=401, detail="Invalid credentials.")

    # Step 3: Successful login
    user.failed_attempts = 0
    user.locked_until = None
    user.last_login_at = datetime.utcnow()
    await db.commit()

    access_token = security.create_access_token(user)
    refresh_token = security.create_refresh_token(user)
    await audit_service.log(action="LOGIN_SUCCESS", user_id=user.id)

    response.set_cookie("refresh_token", refresh_token, httponly=True, secure=True, samesite="strict")
    return TokenResponse(access_token=access_token, token_type="bearer")
```

### 6.3 Logout Endpoint Logic
```python
# POST /api/v1/auth/logout  (requires valid Bearer token)
async def logout(current_user: User = Depends(get_current_user), redis: Redis = Depends(get_redis)):
    jti = current_user.token_jti
    ttl = current_user.token_exp - int(datetime.utcnow().timestamp())
    await redis.setex(f"denylist:{jti}", ttl, "revoked")
    await audit_service.log(action="LOGOUT", user_id=current_user.id)
    response.delete_cookie("refresh_token")
    return {"message": "Logged out successfully."}
```

## 8. Technology Choices

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Auth password hashing | `passlib` + bcrypt (cost 12) | Industry standard; resistant to brute-force |
| JWT library | `python-jose` / `PyJWT` | Lightweight; integrates with FastAPI Depends |
| Rate limiting | `slowapi` (FastAPI-compatible) | Per-IP rate limit on login; minimal config |
| Token storage (FE) | Access token in memory; refresh in httpOnly cookie | Mitigates XSS (no localStorage); CSRF mitigated by SameSite=Strict |
| Token denylist | Redis SETEX keyed by JTI | O(1) lookup; auto-expires with token TTL |
| Agent framework | LangGraph (existing) | Stateful multi-step workflows; platform-consistent |
| LLM | Azure OpenAI GPT-4o | Enterprise data boundary; 128k context window |
| PDF parsing | PyMuPDF | Fast, accurate; OCR fallback |
| DOCX parsing | python-docx | Lightweight; handles styles/tables |
| Output validation | Pydantic v2 | Type-safe schema; auto-generates JSON schema |
| API framework | FastAPI (existing) | Async; auto OpenAPI docs; platform-consistent |
| Database | PostgreSQL + JSONB | Relational integrity + flexible SAD content |
| Cache/Broker | Redis | LLM response cache + Celery broker + token denylist |
| Async tasks | Celery + Redis | Decouples long LLM calls from HTTP cycle |
| Real-time updates | Server-Sent Events (SSE) | Lightweight progress push |

## 9. Non-Functional Design

### 9.1 Security
- Login endpoint: rate-limited (10 req/min/IP); account locked after 5 failures for 15 minutes
- Passwords hashed with bcrypt cost 12; never logged or returned in API responses
- Access token expiry: 15 minutes; refresh token: 7 days (httpOnly Secure cookie)
- All protected routes check JWT validity AND Redis denylist
- RBAC: `architect` and `admin` can generate/approve SADs; `reviewer` can view only
- TLS 1.2+ enforced; HSTS headers set
- LLM API keys in Secrets Manager; rotated every 90 days
- Documents sanitised before LLM submission (strip macros, embedded objects)

### 9.2 Scalability
- Generation tasks dispatched to Celery worker pool; Kubernetes HPA on queue depth
- Redis caches LLM responses keyed by `SHA-256(document_content + prompt_version)`
- PostgreSQL connection pooling via PgBouncer
- Auth Service is stateless (token denylist in Redis); horizontally scalable

### 9.3 Observability
- Structured JSON logs for all services including auth events
- Auth metrics: `login_success_total`, `login_failure_total`, `account_lockout_total`
- Agent metrics: `arch_gen_duration_seconds`, `arch_gen_success_total`, `llm_token_usage_total`
- OpenTelemetry distributed tracing: login → JWT middleware → service → LLM call
- Alerting: >10 failed logins/min from single IP triggers security alert

### 9.4 Versioning
- Prompt files versioned in git and tagged; `prompt_version` stored in SAD record
- SAD document versioning: each re-generation creates a new version row

## 10. Test Strategy

### 10.1 Authentication Unit Tests (`backend/services/auth/tests/`)
| Test | Scenario |
|------|----------|
| `test_login_success` | Valid email + password returns 200 with access token + refresh cookie |
| `test_login_wrong_password` | Returns 401; `failed_attempts` incremented |
| `test_login_unknown_email` | Returns 401; no user info disclosed (same error message) |
| `test_login_lockout_trigger` | 5th consecutive failure locks account; returns 423 on 6th |
| `test_login_locked_account` | Locked user returns 423 with time-remaining message |
| `test_login_rate_limit` | >10 requests/min from same IP returns 429 |
| `test_logout_denylists_jti` | After logout, same token returns 401 (replay prevention) |
| `test_refresh_token_valid` | Valid httpOnly cookie issues new access token |
| `test_refresh_token_expired` | Expired refresh cookie returns 401 |
| `test_private_route_no_token` | Request without Bearer returns 401 |
| `test_private_route_bad_token` | Tampered JWT returns 401 |
| `test_rbac_reviewer_cannot_approve` | `reviewer` role gets 403 on approve endpoint |

### 10.2 Agent Unit Tests
- PDF/DOCX parser edge cases (tables, multi-column, embedded images)
- Pydantic schema validation: valid and invalid SAD JSON
- Completeness check: missing component categories trigger retry loop

### 10.3 Integration Tests
- Mock LLM (VCR cassettes): full pipeline upload → generate → retrieve → approve
- Auth integration: login → upload → generate → logout flow with TestClient
- Celery task execution with in-memory broker

### 10.4 Golden-Set Evaluation
- ≥5 reference requirement documents (e-commerce, fintech, healthcare domains)
- Expert-validated expected SADs paired with each document
- Automated precision/recall scoring ≥ 85% on component identification
- Runs in CI on every PR touching agent code

### 10.5 End-to-End Tests (Playwright)
- Full journey: Load app → redirected to Login → enter credentials → land on dashboard → upload document → trigger generation → view SAD → approve → logout → verify redirect to Login
- Locked account: 5 failed logins → verify 423 UI message
- Session expiry: wait for token expiry → silent refresh → continued access

### 10.6 Security Tests
- OWASP ZAP scan on all API endpoints including `/auth/login`
- Prompt injection test cases in uploaded documents
- Verify bcrypt cost factor ≥ 12 in password hash inspection test
- Verify httpOnly + Secure + SameSite flags on refresh cookie
- Verify Redis denylist populated on logout (replay attack test)

### 10.7 Performance Tests
- Locust: 50 concurrent login requests; assert P95 < 500ms
- Locust: 50 concurrent generation requests; assert P95 < 60s
