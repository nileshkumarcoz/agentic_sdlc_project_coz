### 6. Core Logic Implementation

```python
# src/core/largest_number.py

def validate_input(raw_inputs: dict[str, str]) -> ValidationResult:
    parsed = []
    for field in ["number1", "number2", "number3"]:
        value = raw_inputs.get(field, "").strip()
        if not value:
            return ValidationResult(
                is_valid=False,
                error_message=f"Field '{field}' cannot be empty.",
                error_field=field
            )
        try:
            parsed.append(float(value))
        except ValueError:
            return ValidationResult(
                is_valid=False,
                error_message=f"Invalid input: '{value}' is not a valid number.",
                error_field=field
            )
    return ValidationResult(is_valid=True, parsed_values=parsed)


def find_largest(numbers: list[float]) -> float:
    if len(numbers) != 3:
        raise ValueError("Exactly 3 numbers are required.")
    return max(numbers)
```

### 7. Non-Functional Design

#### 7.1 Security
- All inputs treated as untrusted strings; parsed only via `float()` — no `eval()` or `exec()` usage
- REST endpoint validates Content-Type header to prevent unexpected payloads
- Input length capped at 50 characters to prevent DoS via enormous strings

#### 7.2 Scalability
- The feature is stateless and O(1) — scales horizontally with no additional concern
- No database writes; no shared state between requests

#### 7.3 Observability
- Handler logs each request at DEBUG level: inputs received, validation outcome, result
- Errors logged at WARNING level with field name and raw value
- Use Python `logging` module consistent with project-wide logger configuration

```python
import logging
logger = logging.getLogger(__name__)

# In handler:
logger.debug("largest_number request received: inputs=%s", raw_inputs)
logger.warning("Validation failed: field=%s, reason=%s", result.error_field, result.error_message)
logger.info("largest_number result: %s", largest)
```

### 8. Test Strategy

#### 8.1 Unit Tests (`tests/unit/test_largest_number.py`)

| Test Case | Input | Expected Output |
|---|---|---|
| All positive integers | 1, 2, 3 | 3 |
| All negative numbers | -5, -1, -9 | -1 |
| Mixed positive/negative | -10, 0, 5 | 5 |
| Floating-point numbers | 1.1, 2.2, 1.9 | 2.2 |
| Two equal largest values | 5, 5, 3 | 5 |
| All equal values | 7, 7, 7 | 7 |
| Very large numbers | 1e308, 1e307, 0 | 1e308 |
| Non-numeric input (letter) | 'a', 2, 3 | ValidationError on number1 |
| Empty input | '', 2, 3 | ValidationError on number1 |
| Special chars | '@', 2, 3 | ValidationError on number1 |

#### 8.2 Integration Tests
- CLI: Simulate stdin with valid and invalid inputs; assert stdout output
- API: POST to `/api/largest-number` with valid payload → assert 200 + correct `largest`
- API: POST with invalid payload → assert 422 + meaningful `message`

#### 8.3 Test Command
```bash
pytest tests/ --cov=src/core --cov=src/handlers --cov-report=term-missing
```

- Core logic (`largest_number.py`): **100%**

- CLI/API layer: **≥ 80%**
