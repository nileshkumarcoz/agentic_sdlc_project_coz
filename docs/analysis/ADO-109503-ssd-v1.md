# Solution Design Document (SSD)
## Story ID: 109503 — Chatbot Q&A Application

---

### 1. Proposed Architecture

The application follows a **layered, API-first architecture** with the following components:

```
┌─────────────────────────────────────────────┐
│ Frontend (Optional) │
│ Simple Chat UI (HTML/React) │
└──────────────────┬──────────────────────────┘
 │ HTTP / WebSocket
┌──────────────────▼──────────────────────────┐
│ API Layer │
│ FastAPI Application (Python) │
│ POST /api/chat │
│ GET /api/health │
└──────────────────┬──────────────────────────┘
 │
┌──────────────────▼──────────────────────────┐
│ Q&A Service Layer │
│ - Session Manager │
│ - Prompt Builder │
│ - LLM Client (OpenAI / Local LLM) │
│ - Response Filter (Q&A-only guard) │
└──────────────────┬──────────────────────────┘
 │
┌──────────────────▼──────────────────────────┐
│ Infrastructure │
│ - In-Memory Session Store (Redis optional) │
│ - Logging (structlog / Python logging) │
│ - Config (.env / settings.py) │
└─────────────────────────────────────────────┘
```

---

### 2. Components

| Component | Description | Technology |
|---|---|---|
| **API Layer** | REST endpoints for Q&A interaction and health check | FastAPI (Python) |
| **Session Manager** | Maintains conversation history per session_id | In-memory dict / Redis |
| **Prompt Builder** | Constructs system + user message payload for LLM | Python |
| **LLM Client** | Sends requests to LLM backend and receives responses | OpenAI SDK / LangChain |
| **Q&A Guard** | Detects and rejects non-Q&A requests (task execution, etc.) | Rule-based + prompt engineering |
| **Logger** | Structured logging of all interactions | Python structlog |
| **Config Manager** | Reads environment variables and settings | Pydantic BaseSettings |
| **Frontend UI** | Optional simple chat interface | HTML + Vanilla JS or React |

### 3. Data Model

#### 3.1 Chat Request
```json
{
 "session_id": "string (UUID)",
 "question": "string (user's natural language question)"
}
```

#### 3.2 Chat Response
```json
{
 "session_id": "string (UUID)",
 "answer": "string (LLM-generated answer)",
 "timestamp": "ISO8601 datetime",
 "status": "success | out_of_scope | error"
}
```

#### 3.3 Session History Entry
```json
{
 "role": "user | assistant",
 "content": "string",
 "timestamp": "ISO8601 datetime"
}
```

#### 3.4 Session Store (In-Memory)
```python
sessions: Dict[str, List[HistoryEntry]] = {}
# Key: session_id (UUID string)
# Value: ordered list of HistoryEntry objects
```

### 4. Key APIs / Interfaces

#### 4.1 POST `/api/chat`
**Purpose**: Submit a question and receive an answer.

**Request Body**:
```json
{
 "session_id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
 "question": "What is the capital of France?"
}
```

**Response (200 OK)**:
```json
{
 "session_id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
 "answer": "The capital of France is Paris.",
 "timestamp": "2024-01-15T10:30:00Z",
 "status": "success"
}
```

**Response (200 — Out of Scope)**:
```json
{
 "session_id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
 "answer": "I can only answer questions. Please ask me something.",
 "timestamp": "2024-01-15T10:30:01Z",
 "status": "out_of_scope"
}
```

#### 4.2 GET `/api/health`
**Purpose**: Health check for monitoring.

**Response (200 OK)**:
```json
{ "status": "healthy", "version": "1.0.0" }
```

#### 4.3 DELETE `/api/session/{session_id}`
**Purpose**: Clear session history for a given session.

**Response (200 OK)**:
```json
{ "message": "Session cleared." }
```

### 5. Sequence of Main Flow

```
User → API Layer → Session Manager → Prompt Builder → LLM Client → API Layer → User

1. User sends POST /api/chat { session_id, question }
2. API Layer validates request schema (Pydantic)
3. Session Manager retrieves existing conversation history for session_id
4. Q&A Guard checks if the question is a valid Q&A request
 a. If NOT → return out_of_scope response immediately
 b. If YES → proceed
5. Prompt Builder constructs:
 - System prompt: "You are a Q&A assistant. Only answer questions. Do not perform tasks."
 - Conversation history (last N turns)
 - Current user question
6. LLM Client sends the constructed payload to LLM backend
7. LLM returns answer text
8. Session Manager appends user question + assistant answer to history
9. Logger records interaction (session_id, question, answer, latency, timestamp)
10. API Layer returns Chat Response to user
```

| Layer | Choice | Rationale |

| Testing | **pytest + httpx** | Unit and integration testing of API endpoints |
| CI | **GitHub Actions** (existing in repo) | Automated test runs on PR |

### 8. Non-Functional Design

#### 8.1 Security
- **Input Sanitization**: All inputs validated via Pydantic; max character limit enforced (e.g., 2000 chars).
- **API Key Protection**: LLM API keys stored in `.env`, never committed to source control.
- **Rate Limiting**: FastAPI middleware (`slowapi`) to limit requests per IP (e.g., 30 req/min).
- **No PII Storage**: Session history stored in-memory only; no persistent DB by default.
- **CORS**: Restrict allowed origins in production.

#### 8.2 Scalability
- FastAPI's async handlers support high concurrency.
- Replace in-memory session store with **Redis** for horizontal scaling.
- Stateless API design allows multiple instances behind a load balancer.
- LLM calls are async (using `openai` async client).

#### 8.3 Observability
- **Structured Logs**: Every request logged with `session_id`, `question_length`, `response_status`, `latency_ms`, `timestamp`.
- **Health Endpoint**: `GET /api/health` for uptime monitoring.
- **Metrics** (optional extension): Prometheus metrics via `prometheus-fastapi-instrumentator`.
- **Error Tracking**: Unhandled exceptions logged with full stack trace.

### 9. Test Strategy

| Test Type | Scope | Tool | Target Coverage |
|---|---|---|---|
| **Unit Tests** | `session_manager`, `prompt_builder`, `qa_guard`, `llm_client` (mocked) | pytest | ≥ 70% |
| **Integration Tests** | `POST /api/chat`, `GET /api/health`, `DELETE /api/session/{id}` | pytest + httpx | All endpoints |
| **Contract Tests** | Validate request/response schema conformance | pytest + Pydantic | All schemas |
| **Edge Case Tests** | Empty question, very long input, unknown session_id, out-of-scope question | pytest | All edge paths |
| **Load Tests** | 50 concurrent users, measure P95 latency | locust | NFR-01, NFR-03 |

#### Key Test Scenarios:
1. ✅ Valid question → valid answer returned with `status: success`.
2. ✅ Out-of-scope command ("Delete this file") → `status: out_of_scope` with redirect message.
3. ✅ Multi-turn conversation maintains context across turns.
4. ✅ Empty or whitespace-only question → 422 Unprocessable Entity.
5. ✅ Unknown session_id → new session created automatically.
6. ✅ LLM API timeout → 504 Gateway Timeout with user-friendly error.
7. ✅ Rate limit exceeded → 429 Too Many Requests.

### 11. Future Extensibility
- **RAG (Retrieval-Augmented Generation)**: Add a vector store (e.g., Chroma, Pinecone) to answer domain-specific questions from documents.
- **Authentication**: Add JWT-based auth for multi-user environments.
- **Persistent Sessions**: Migrate session store to PostgreSQL for history persistence.
- **Streaming Responses**: Use SSE (Server-Sent Events) for token-by-token streaming.
- **Agentic Extension**: Plug into the broader agentic SDLC pipeline for SDLC-specific Q&A.
