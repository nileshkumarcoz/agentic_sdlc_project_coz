# Solution Design Document

## Story ID: 109519 — Factorial Calculator

---

## 1. Proposed Architecture & Components

The solution is implemented within the **`agentic_sdlc_project_coz`** repository following a layered architecture:

```
┌─────────────────────────────────────────────┐
│              Presentation Layer             │
│  (Flask route / CLI entry-point / HTML form)│
└────────────────────┬────────────────────────┘
                     │ calls
┌────────────────────▼────────────────────────┐
│              Service Layer                  │
│  factorial_service.py                       │
│  - validate_input(raw_input) → int          │
│  - compute_factorial(n: int) → int          │
└────────────────────┬────────────────────────┘
                     │ pure functions
┌────────────────────▼────────────────────────┐
│              Utility / Core Layer           │
│  factorial_core.py                          │
│  - factorial(n: int) → int  (iterative)     │
└─────────────────────────────────────────────┘
```

### Component Descriptions

| Component | File Path | Responsibility |
|---|---|---|
| `FactorialView` / Route | `app/views/factorial_view.py` | Accepts HTTP POST or CLI args, calls service, renders response |
| `FactorialService` | `app/services/factorial_service.py` | Orchestrates validation + computation, returns result or raises `ValidationError` |
| `FactorialCore` | `app/core/factorial_core.py` | Pure mathematical function; no I/O, no side effects |
| `ErrorMessages` | `app/constants/messages.py` | Centralised human-readable error strings |
| `Templates` | `app/templates/factorial.html` | Jinja2 template rendering input form, result, and errors |
| `Tests` | `tests/test_factorial_*.py` | Unit + integration test suite |

## 2. Data Model

No persistent storage is required. The in-memory data contract between layers:

### Request DTO
```python
@dataclass
class FactorialRequest:
    raw_input: str          # raw string from user (pre-validation)
```

### Response DTO
```python
@dataclass
class FactorialResponse:
    success: bool
    input_value: int | None       # parsed integer, None on error
    result: int | None            # n! result, None on error
    error_message: str | None     # human-readable error, None on success
```

# app/core/factorial_core.py
def factorial(n: int) -> int:
    """Compute n! iteratively. Assumes n >= 0 and n <= MAX_INPUT."""
    result = 1
    for i in range(2, n + 1):
        result *= i
    return result

# app/services/factorial_service.py
MAX_INPUT = 10_000

      - negative integers
      - integers exceeding MAX_INPUT
    Returns parsed non-negative integer on success.
    """

## 6. Non-Functional Design

### 6.1 Security
- All input is treated as untrusted strings until explicitly validated.
- `validate_input` strips whitespace and checks type before any computation.
- No `eval()` or dynamic code execution is used for computation.
- MAX_INPUT cap (10,000) prevents resource exhaustion / DoS via large integer computation.

### 6.2 Scalability
- The iterative algorithm is O(n) time and O(1) auxiliary space (beyond the result integer).
- The endpoint is stateless; no shared mutable state — scales horizontally without changes.
- For n up to 10,000, computation completes in < 50 ms on commodity hardware.

### 6.3 Observability
- Python `logging` module used in the service layer to log:
  - `INFO`: successful computation with input and result length (digits).
  - `WARNING`: invalid input attempts with the raw input value (sanitised).
- Log format: `%(asctime)s [%(levelname)s] factorial_service — %(message)s`
- Future: expose a `/metrics` endpoint (Prometheus counter) for calculation request rate and error rate.

## 8. Test Strategy

### 8.1 Unit Tests — `tests/test_factorial_core.py`

| Test Case | Input | Expected Output |
|---|---|---|
| Base case zero | 0 | 1 |
| Base case one | 1 | 1 |
| Small positive | 5 | 120 |
| Medium positive | 10 | 3628800 |
| Large positive | 20 | 2432902008176640000 |

### 8.2 Unit Tests — `tests/test_factorial_service.py`

| Test Case | Input | Expected Behaviour |
|---|---|---|
| Valid integer string | `"7"` | Returns `FactorialResponse(success=True, result=5040)` |
| Negative integer | `"-1"` | Raises / returns error: ERR_NEGATIVE_NUMBER |
| Float string | `"3.5"` | Returns error: ERR_NOT_INTEGER |
| Alpha string | `"abc"` | Returns error: ERR_NOT_INTEGER |
| Empty string | `""` | Returns error: ERR_EMPTY_INPUT |
| Exceeds max | `"10001"` | Returns error: ERR_EXCEEDS_MAX |
| Boundary max | `"10000"` | Returns success |
| Leading whitespace | `" 5 "` | Returns success (strip applied) |

### 8.3 Integration Tests — `tests/test_factorial_integration.py`

- POST `/factorial` with valid JSON → 200 + correct result.
- POST `/factorial` with negative number → 422 + error message.
- POST `/factorial` with missing field → 400.

### 8.4 CI Gate

- All tests must pass and coverage must be ≥ 90% on `app/core/` and `app/services/` before merge to `main`.
