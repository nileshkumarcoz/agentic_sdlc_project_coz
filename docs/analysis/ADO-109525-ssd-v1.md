## 5. Sequence Diagrams

### 5.1 Synchronous API Flow
```
Client → API Gateway → Lambda (api_handler) → Secrets Manager (cold start only)
 Lambda → DynamoDB (read/write)
 Lambda → API Gateway → Client
 (CloudWatch Logs + X-Ray throughout)
```

### 5.2 Async Event Processing Flow
```
Producer → SQS Queue → Lambda (event_processor) [batch of 1-10 messages]
 Success → Delete messages from SQS
 Partial failure → SQS retries failed messages up to maxReceiveCount
 Full failure → DLQ → CloudWatch Alarm → SNS notification
```

### 5.3 Scheduled Job Flow
```
EventBridge (cron) → Lambda (scheduler)
 → Fetch config from SSM
 → Execute job logic
 → Log result to CloudWatch
 → Emit custom metric
```

## 7. Technology Choices

| Concern | Choice | Rationale |
|---|---|---|
| Runtime | Python 3.11 | Fast cold starts, broad library support, likely existing repo language |
| IaC | AWS SAM | Native Lambda support, local testing via `sam local invoke` |
| Observability SDK | AWS Lambda Powertools (Python) | Structured logging, tracing, metrics out-of-the-box |
| Secrets | AWS Secrets Manager | Encrypted, rotatable, SDK cached |
| Async event source | Amazon SQS (Standard) | High throughput, ReportBatchItemFailures support |
| Scheduling | Amazon EventBridge | Cron/rate rules, serverless, no infrastructure |
| Tracing | AWS X-Ray | Native Lambda integration, service map |
| CI/CD | GitHub Actions | Assumed from repo hosting; SAM deploy step |
| Testing | pytest + moto | Unit tests with mocked AWS services |
| API layer | API Gateway HTTP API | Lower latency, lower cost than REST API |

## 9. Non-Functional Design

### 9.1 Security
- **IAM Least Privilege**: Each Lambda has a dedicated execution role scoped to only the AWS services it needs.
- **No plaintext secrets**: All secrets fetched from Secrets Manager at runtime; Lambda Powertools Parameters extension caches with 5-min TTL.
- **TLS enforced**: All AWS SDK calls use HTTPS by default; API Gateway enforces TLS 1.2+.
- **VPC (if DB access needed)**: Lambda placed in private subnet with NAT Gateway for internet-bound calls.
- **Resource-based policies**: API Gateway resource policy restricts invocations to known IP ranges if internal.

### 9.2 Scalability
- **Reserved Concurrency**: Set per-function reserved concurrency to prevent noisy-neighbour effect.
- **SQS batch window**: `MaximumBatchingWindowInSeconds: 5` to increase batch efficiency at high throughput.
- **Provisioned Concurrency**: Applied to `api_handler` for production to eliminate cold starts on p95 critical path.
- **DynamoDB on-demand**: Auto-scales with Lambda burst traffic.

### 9.3 Observability
```
CloudWatch Dashboards:
 - Lambda Duration (p50 / p95 / p99)
 - Error rate & throttle count
 - SQS queue depth & DLQ message count
 - Custom business metrics (via Powertools Metrics)

CloudWatch Alarms:
 - DLQ messages > 0 → SNS alert to on-call
 - Lambda error rate > 1% over 5 min → SNS alert
 - Lambda duration p95 > 10s → SNS alert

X-Ray Service Map:
 - End-to-end trace from API Gateway → Lambda → DynamoDB
```

## 10. Test Strategy

| Test Type | Tool | Scope | Location |
|---|---|---|---|
| Unit Tests | pytest + moto | Handler logic, utility functions, edge cases | `lambdas/*/tests/test_unit.py` |
| Integration Tests | pytest + boto3 (real AWS) | Lambda ↔ SQS ↔ DynamoDB round-trip | `lambdas/*/tests/test_integration.py` |
| Contract Tests | pytest + JSON Schema | API Gateway request/response shapes | `lambdas/api_handler/tests/` |
| Load Tests | Artillery / Locust | Concurrency, cold start, p95 latency | Separate `load_tests/` folder |
| IaC Validation | cfn-lint + SAM validate | Template syntax and best-practice checks | CI `test` job |
| Security Scan | checkov | IAM policies, security groups in IaC | CI `test` job |

### Sample Unit Test
```python
# lambdas/api_handler/tests/test_unit.py
import json
import pytest
from moto import mock_dynamodb
from api_handler.handler import lambda_handler

@mock_dynamodb
def test_lambda_handler_returns_200(api_gw_event, lambda_context):
 response = lambda_handler(api_gw_event, lambda_context)
 assert response["statusCode"] == 200
 body = json.loads(response["body"])
 assert "requestId" in body

def test_lambda_handler_bad_payload_returns_400(lambda_context):
 event = {"body": json.dumps({})}
 response = lambda_handler(event, lambda_context)
 assert response["statusCode"] == 400
```
