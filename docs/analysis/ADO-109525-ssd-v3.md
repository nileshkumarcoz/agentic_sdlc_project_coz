## 3. Caching Strategy (NEW — Primary Addition)

### 3.1 Two-Layer Cache Architecture

```
Request
 │
 ▼
┌─────────────────────────────┐
│ Layer 1: In-Memory Cache │ ← Lambda execution context (module-level dict)
│ TTL enforced by timestamp │ per container; survives warm invocations
│ Zero network overhead │
└──────────────┬──────────────┘
 │ MISS
 ▼
┌─────────────────────────────┐
│ Layer 2: ElastiCache Redis │ ← Shared across all Lambda containers
│ Cluster Mode (Multi-AZ) │ survives Lambda scaling; sub-ms latency
│ TLS + Auth Token │
└──────────────┬──────────────┘
 │ MISS
 ▼
┌─────────────────────────────┐
│ Source of Truth │ ← DynamoDB / Cognito / SSM / External API
│ Write result back to L2+L1 │
└─────────────────────────────┘
```

### 3.2 Cache Key Design & TTL Policy

| Cache Layer | Key Pattern | TTL | Data Cached | Invalidation Strategy |
|---|---|---|---|---|
| In-Memory (L1) | `jwks:{region}:{pool_id}` | 5 min | Cognito JWKS public keys | TTL expiry; Lambda container recycle |
| In-Memory (L1) | `ssm:{param_name}` | 5 min | SSM Parameter Store values | TTL expiry |
| In-Memory (L1) | `cognito_config` | 5 min | Cognito User Pool / Client IDs | TTL expiry |
| Redis (L2) | `user:profile:{sub}` | 60 s | User profile from DynamoDB | Write-through on profile update |
| Redis (L2) | `status:{id}` | 30 s | Processing status from DynamoDB | Write-through on status change |
| Redis (L2) | `ext_api:{hash(params)}` | 30 s | External API responses | TTL expiry; explicit delete on update |
| Redis (L2) | `rate:login:{ip}` | 60 s | Login attempt counter (integer) | TTL expiry (sliding window) |
| Redis (L2) | `session_meta:{sub}` | 1 hr | Non-sensitive session metadata | Delete on logout |

### 3.3 Cache Abstraction Implementation

```python
# shared/utils/cache.py
import time
import json
import hashlib
from typing import Any, Optional, Callable
import redis
import os

# ── Layer 1: In-process in-memory cache (module-level, survives warm invocations) ──
_L1_STORE: dict[str, tuple[Any, float]] = {} # {key: (value, expire_at_epoch)}

def _l1_get(key: str) -> Optional[Any]:
 """Return cached value if not expired, else None."""
 entry = _L1_STORE.get(key)
 if entry and time.monotonic() < entry[1]:
 return entry[0]
 _L1_STORE.pop(key, None)
 return None

def _l1_set(key: str, value: Any, ttl_seconds: int) -> None:
 _L1_STORE[key] = (value, time.monotonic() + ttl_seconds)

# ── Layer 2: ElastiCache Redis (lazy singleton, reused across warm invocations) ──
_redis_client: Optional[redis.Redis] = None

def _get_redis() -> redis.Redis:
 global _redis_client
 if _redis_client is None:
 _redis_client = redis.Redis(
 host=os.environ["REDIS_HOST"],
 port=int(os.environ.get("REDIS_PORT", 6379)),
 ssl=True,
 password=os.environ["REDIS_AUTH_TOKEN"], # from Secrets Manager at init
 decode_responses=True,
 socket_connect_timeout=0.5, # fast fail if Redis unreachable
 socket_timeout=0.5,
 )
 return _redis_client

def _l2_get(key: str) -> Optional[Any]:
 try:
 raw = _get_redis().get(key)
 return json.loads(raw) if raw else None
 except Exception:
 return None # graceful degradation: Redis failure is non-fatal

def _l2_set(key: str, value: Any, ttl_seconds: int) -> None:
 try:
 _get_redis().setex(key, ttl_seconds, json.dumps(value))
 except Exception:
 pass # non-fatal

# ── Public API ──
def get_cached(
 key: str,
 loader: Callable[[], Any],
 l1_ttl: int = 300,
 l2_ttl: int = 60,
) -> Any:
 """
 Try L1 → L2 → loader(). Write back through both layers on miss.
 loader must be a zero-argument callable returning the fresh value.
 """
 # L1 hit
 val = _l1_get(key)
 if val is not None:
 return val

 # L2 hit
 val = _l2_get(key)
 if val is not None:
 _l1_set(key, val, l1_ttl) # promote to L1
 return val

 # Full miss — load from source
 val = loader()
 _l2_set(key, val, l2_ttl)
 _l1_set(key, val, l1_ttl)
 return val

def invalidate(key: str) -> None:
 """Remove key from both cache layers (use on writes)."""
 _L1_STORE.pop(key, None)
 try:
 _get_redis().delete(key)
 except Exception:
 pass

def increment_rate_counter(key: str, window_seconds: int = 60) -> int:
 """
 Atomic increment for rate-limit counters. Returns new count.
 Sets TTL only on first increment (NX flag).
 """
 try:
 pipe = _get_redis().pipeline()
 pipe.incr(key)
 pipe.expire(key, window_seconds, nx=True)
 result = pipe.execute()
 return result[0]
 except Exception:
 return 0 # fail open on Redis error
```

### 3.4 JWKS In-Memory Cache (Auth Utility)

```python
# shared/utils/auth.py
import time
import json
import urllib.request
from jose import jwt, jwk
from shared.utils.cache import _l1_get, _l1_set

_JWKS_TTL = 300 # 5 minutes

def _fetch_jwks(region: str, user_pool_id: str) -> dict:
 url = f"https://cognito-idp.{region}.amazonaws.com/{user_pool_id}/.well-known/jwks.json"
 with urllib.request.urlopen(url, timeout=2) as resp:
 return json.loads(resp.read())

def get_jwks(region: str, user_pool_id: str) -> dict:
 """Returns JWKS from L1 in-memory cache, fetching only on cold/expiry."""
 cache_key = f"jwks:{region}:{user_pool_id}"
 cached = _l1_get(cache_key)
 if cached:
 return cached
 keys = _fetch_jwks(region, user_pool_id)
 _l1_set(cache_key, keys, _JWKS_TTL)
 return keys

def decode_and_verify_jwt(token: str, region: str, user_pool_id: str) -> dict:
 """
 Verifies JWT against cached JWKS. Does NOT hit Cognito on warm invocations.
 """
 jwks = get_jwks(region, user_pool_id)
 # python-jose handles kid lookup, signature verification, expiry
 return jwt.decode(
 token,
 jwks,
 algorithms=["RS256"],
 options={"verify_at_hash": False},
 )
```

### 3.6 Cache-Based Rate Limiting (auth_handler)

```python
# lambdas/auth_handler/handler.py (excerpt)
from shared.utils.cache import increment_rate_counter

_MAX_LOGIN_ATTEMPTS = 10 # per IP per 60-second window

def login(event: dict) -> dict:
 ip = event["requestContext"]["http"]["sourceIp"]
 rate_key = f"rate:login:{ip}"
 count = increment_rate_counter(rate_key, window_seconds=60)
 if count > _MAX_LOGIN_ATTEMPTS:
 return {"statusCode": 429, "body": json.dumps({"message": "Too many login attempts"})}
 # ... proceed with Cognito authentication ...
```

### 3.7 Cache Warming (Scheduled Lambda)

```python
# lambdas/scheduler/handler.py (excerpt)
from shared.utils.auth import get_jwks
from shared.utils.cache import _l2_set
import os

def warm_cache() -> None:
 """
 Pre-populate Redis with JWKS and critical SSM parameters
 so the first post-deploy Lambda invocations hit a warm L2 cache.
 Called by EventBridge every 4 minutes (before L2 TTL of 5 min expires).
 """
 region = os.environ["AWS_REGION"]
 pool_id = os.environ["COGNITO_USER_POOL_ID"]
 jwks = get_jwks(region, pool_id)
 _l2_set(f"jwks:{region}:{pool_id}", jwks, ttl_seconds=300)
```

## 6. Sequence Diagrams

### 6.1 Login Flow with Cache-Based Rate Limiting (UPDATED)
```
Client
 │
 │ POST /auth/login {email, password}
 ▼
API Gateway → Lambda: auth_handler
 │── 1. Extract source IP from event context
 │── 2. increment_rate_counter("rate:login:{ip}", 60s)
 │ └─▶ Redis INCR+EXPIRE (atomic pipeline)
 │ ├─▶ count > 10 → return 429 Too Many Requests
 │ └─▶ count ≤ 10 → continue
 │── 3. Validate payload (Pydantic)
 │── 4. CognitoAuthClient.login(email, password)
 │ └─▶ Cognito: InitiateAuth
 │ ├─▶ 401 NotAuthorizedException
 │ └─▶ 200 {AccessToken, RefreshToken, ExpiresIn}
 │── 5. Write audit record to DynamoDB
 │── 6. Cache session_meta in Redis (key: session_meta:{sub}, TTL 1hr)
 │── 7. Return 200 TokenResponse
 ▼
Client stores tokens
```

### 6.2 Protected API — GET /v1/status/{id} with Two-Layer Cache (NEW)
```
Client + JWT
 │
 │ GET /v1/status/{id}
 │ Authorization: Bearer <access_token>
 ▼
API Gateway → Cognito JWT Authorizer (validates token — no Lambda cost)
 │
 ▼
Lambda: api_handler
 │── 1. Try L1 in-memory cache.get("status:{id}")
 │ └─▶ HIT → return immediately (0 ms network)
 │
 │── 2. L1 MISS → try L2 Redis.get("status:{id}")
 │ └─▶ HIT → write to L1, return (~0.5 ms)
 │
 │── 3. L2 MISS → DynamoDB.GetItem("status:{id}")
 │ └─▶ Write result to Redis (TTL 30s)
 │ └─▶ Write result to L1 (TTL 30s)
 │ └─▶ return result (~5-10 ms)
 ▼
Client
```

### 6.3 POST /v1/process with Write-Through Invalidation
```
Lambda: api_handler
 │── Execute business logic
 │── Write updated status to DynamoDB
 │── invalidate("status:{id}") ← removes stale entry from Redis + L1
 │── Return 200
```

### 6.4 Logout with Cache Invalidation
```
Lambda: auth_handler
 │── CognitoAuthClient.logout(access_token) → GlobalSignOut
 │── invalidate("session_meta:{sub}") ← evict from Redis + L1
 │── Write audit record (LOGOUT)
 │── Return 200
```

### 6.5 Cache Warming (Scheduled)
```
EventBridge (every 4 min)
 │
 ▼
Lambda: scheduler
 │── warm_cache()
 │ └─▶ fetch JWKS from Cognito
 │ └─▶ Redis SET jwks:{region}:{pool_id} TTL=300s
 │── Return
```

### 6.6 JWKS Verification — In-Memory Cache Hit Path
```
shared/utils/auth.decode_and_verify_jwt(token)
 │── L1 get("jwks:{region}:{pool_id}")
 │ └─▶ HIT (warm container) → verify locally, 0 HTTP calls
 │ └─▶ MISS (cold container or TTL expired)
 │── L2 Redis get("jwks:{region}:{pool_id}")
 │ └─▶ HIT → promote to L1, verify locally
 │ └─▶ MISS → fetch from Cognito JWKS URL
 │ → write to L2 + L1
```

## 8. Technology Choices

| Concern | Choice | Rationale |
|---|---|---|
| L1 Cache | **Python module-level dict** | Zero latency; survives warm Lambda invocations; no dependencies |
| L2 Cache | **Amazon ElastiCache for Redis 7** | Sub-ms shared cache; atomic INCR for rate limiting; TLS + auth token; Multi-AZ |
| Cache Client | **redis-py 5.x** | Mature, supports TLS, pipeline, RESP3; async-compatible |
| Cache Warming | **EventBridge scheduled Lambda** | Pre-populates Redis before cold-start traffic spikes |
| Identity / Auth | **Amazon Cognito User Pools** | Managed JWT, password hashing, lockout |
| API Authorization | **Cognito JWT Authorizer** | Zero-code token validation at Gateway layer |
| Runtime | Python 3.11 | Fast cold starts; Powertools support |
| IaC | AWS SAM | Native Lambda + Cognito + ElastiCache + API Gateway |
| Observability | AWS Lambda Powertools + X-Ray | Structured logging (tokens masked), distributed tracing |
| Async events | Amazon SQS + DLQ | ReportBatchItemFailures support |
| CI/CD | GitHub Actions | SAM build + deploy |
| Testing | pytest + moto + fakeredis | Unit + integration test coverage including cache layer |

## 9. Security Design

### 9.1 Authentication Security Controls
| Control | Implementation |
|---|---|
| Password hashing | Delegated to Cognito |
| Token expiry | Access: 1 hour; Refresh: 30 days |
| Token revocation | `GlobalSignOut` on logout; `session_meta` evicted from Redis |
| Brute-force protection | Redis `increment_rate_counter` (10 req/60s per IP) + WAF rate-limit rule |
| No token logging | `log_event=False` on auth Lambda; Authorization header masked |
| HTTPS only | API Gateway enforces TLS 1.2+ |
| Redis security | TLS in-transit + auth token from Secrets Manager; security group restricts to Lambda SG only |

### 9.2 Cache Security
| Concern | Approach |
|---|---|
| Sensitive data in cache | Never cache raw JWT tokens or passwords; only non-sensitive metadata and public JWKS |
| Cache poisoning | Redis auth token required; security group allows only Lambda SG; no public endpoint |
| Redis auth token rotation | Stored in Secrets Manager; rotated via Lambda-triggered rotation policy |
| Cache key collisions | Namespaced keys (prefix:type:id) prevent cross-tenant data leakage |

### 9.3 IAM Least Privilege
- `AuthHandlerRole`: Cognito SignUp/InitiateAuth/GlobalSignOut + DynamoDB PutItem + Secrets Manager (Redis token)
- `ApiHandlerRole`: DynamoDB GetItem/PutItem + Secrets Manager (Redis token)
- `EventProcessorRole`: SQS ReceiveMessage/DeleteMessage + target writes
- `SchedulerRole`: SSM GetParameter + CloudWatch PutMetricData + Secrets Manager (Redis token)

## 10. Non-Functional Design

### 10.1 Scalability
- Redis cluster scales vertically (node type) and supports read replicas for read-heavy workloads
- Lambda concurrency reserved per function to prevent noisy-neighbour effects
- DynamoDB on-demand billing — bursts with Lambda
- Cache significantly reduces DynamoDB RCU consumption (cost optimization)

### 10.2 Observability
```
CloudWatch Dashboards:
 - Cache hit/miss rate (custom metric from cache.py)
 - Redis memory utilization and evictions
 - Lambda Duration p50/p95/p99 per function
 - Auth: login success/failure rate
 - SQS queue depth & DLQ message count

CloudWatch Alarms:
 - Redis eviction rate > 0 → SNS (cache under memory pressure)
 - Redis connection errors > 5 in 1 min → SNS
 - Cache hit rate < 50% over 5 min → SNS (investigate cache sizing)
 - Login failure rate > 5% over 5 min → SNS (potential attack)
 - DLQ messages > 0 → SNS
 - Lambda error rate > 1% → SNS

Custom Metrics emitted by cache.py:
 - CacheHit / CacheMiss counters per key namespace
 - RateLimitBlocked counter (for security dashboards)
```

### 10.3 Cache Sizing Guidance
| Environment | Redis Node Type | Rationale |
|---|---|---|
| dev | cache.t4g.micro | Minimal cost |
| staging | cache.t4g.small | Mirrors prod topology |
| prod | cache.r7g.large | 13 GB RAM; supports millions of cached keys |
