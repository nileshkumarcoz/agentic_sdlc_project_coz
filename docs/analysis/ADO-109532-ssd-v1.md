### 3. Data Model

```python
# models.py
from dataclasses import dataclass, field
from datetime import datetime
from typing import Any

@dataclass(frozen=True)
class WatchEvent:
 event_id: str # uuid4
 source_id: str # logical name of the log source
 pattern_name: str # name of the matched pattern
 matched_line: str # raw log line
 timestamp: datetime = field(default_factory=datetime.utcnow)
 metadata: dict[str, Any] = field(default_factory=dict)

@dataclass
class PatternConfig:
 name: str # unique identifier
 regex: str # raw regex string
 severity: str = "INFO" # INFO | WARN | ERROR | CRITICAL
```

### 4. Key APIs / Interfaces

#### 4.1 `LogWatcher`
```python
class LogWatcher:
 def __init__(
 self,
 source: LogSource,
 patterns: list[PatternConfig],
 history_limit: int = 1000,
 poll_interval_ms: int = 100,
 ) -> None: ...

 def register_callback(self, fn: Callable[[WatchEvent], None]) -> None:
 """Register a sync callback; multiple callbacks supported."""

 def start(self) -> None:
 """Start watching in a background thread."""

 def stop(self, timeout_s: float = 5.0) -> None:
 """Signal stop and join the background thread."""

 def get_history(self) -> list[WatchEvent]:
 """Return a snapshot of all events recorded so far."""

 def clear_history(self) -> None: ...
```

#### 4.2 `LogSource` ABC
```python
class LogSource(ABC):
 @property
 @abstractmethod
 def source_id(self) -> str: ...

 @abstractmethod
 def lines(self) -> Iterator[str]:
 """Yield log lines; blocks in tail mode."""

 @abstractmethod
 def close(self) -> None: ...
```

#### 4.3 `PatternRegistry`
```python
class PatternRegistry:
 def register(self, config: PatternConfig) -> None: ...
 def match_all(self, line: str) -> list[tuple[str, re.Match]]: ...
 # Returns list of (pattern_name, match_object) for all matching patterns
```

### 6. Technology Choices

| Concern | Choice | Rationale |
|---|---|---|
| Language | Python 3.11+ | Consistent with repo; rich stdlib for threading & regex |
| File watching | `watchdog` 3.x library | Cross-platform `inotify`/`FSEvents`; avoids busy-poll |
| Regex engine | `re` (stdlib) + `re.compile` at registration | Fast; validate on registration to catch bad patterns early |
| Concurrency | `threading.Thread` + `threading.Event` for stop signal | Simpler than asyncio for file I/O; async wrapper can be layered on top |
| Async bridge | `asyncio.Queue` (optional) | Allows async consumers to subscribe without blocking |
| Testing | `pytest`, `pytest-mock`, `tmp_path` fixture | Already standard in Python projects |
| Linting/types | `mypy`, `ruff` | Consistent with modern Python SDLC projects |

### 8. Non-Functional Design

#### 8.1 Security
- **Secrets scrubbing**: `PatternConfig` may include a `scrub_groups` list; matched regex groups in those positions are replaced with `***` before the event is stored or dispatched.
- **File permissions**: `FileLogSource` checks read permission before opening and raises `PermissionError` cleanly.
- **No external network calls**: The watcher is fully local; no telemetry.

#### 8.2 Scalability
- Each `LogWatcher` instance owns exactly one background thread; scale horizontally by instantiating one watcher per log source.
- `EventHistoryStore` uses `collections.deque(maxlen=history_limit)` — O(1) append, bounded memory.
- Batch mode processes lines without sleep; tail mode uses `watchdog` observer events to avoid spin loops.

#### 8.3 Observability
- The watcher emits its own internal logs via Python `logging` module under logger `log_watcher` at DEBUG/INFO/WARNING levels.
- `get_history()` and `len(get_history())` provide instant insight into watcher state.
- Expose a `stats()` method returning `{lines_processed, events_emitted, errors_in_callbacks}`.

### 9. Test Strategy

#### 9.1 Unit Tests
| Test Case | Approach |
|---|---|
| Pattern matching — positive | `PatternRegistry.match_all()` with known lines & patterns |
| Pattern matching — negative | Assert empty list returned for non-matching lines |
| Callback invocation | Mock callback; assert called with correct `WatchEvent` fields |
| Multiple callbacks | Register 3 mocks; assert all invoked per match |
| Callback exception isolation | Callback raises; assert watcher thread continues |
| Start/Stop lifecycle | Start watcher on `StreamLogSource(StringIO(...))`; write lines; stop; assert history |
| Tail mode detection | Use `tmp_path` to create real file; watcher starts; test appends lines; assert events within 1 s |
| Empty file | Assert no events, clean stop |
| Very long line (>1 MB) | Assert handled without crash |
| History limit | Push `history_limit + 10` events; assert `len(get_history()) == history_limit` |
| Stats accuracy | Assert `lines_processed` and `events_emitted` counters are correct |

#### 9.2 Integration Tests
| Test Case | Approach |
|---|---|
| Pipeline log file watch | Start a pipeline component, point `FileLogSource` at its log file, assert known startup messages are captured as events |
| Concurrent watchers | Spin up 5 watchers on 5 different temp files; write concurrently; assert no cross-contamination |

#### 9.3 Performance Smoke Test
- Generate a 100,000-line log file.
- Run batch mode watcher with 5 patterns.
- Assert completion in < 10 seconds (≥ 10k lines/sec).

#### 9.4 CI Integration
- Add `pytest tests/unit/test_log_watcher/ tests/integration/test_log_watcher_integration.py` to the existing CI workflow.
- Coverage gate: ≥ 90 % branch coverage on `src/log_watcher/`.
